# 自适应问题求解

管理“当前如何理解和解决问题”：在返工变大前发现错误问题、发力点或执行方式，以低于潜在损失的成本换路。它是薄控制循环；方法、知识、任务状态、研发记忆和工具能力仍归各自载体。

## 一、判断是否需要进入

以下任一情况出现时进入：

- 用户要求重新界定、检查方向、选方法或复盘；
- 问题、结果或关键约束仍有多种会显著改变结果的解释；
- 准备选择第一项实质路径，且选错会造成明显返工；
- 准备进行多来源调研、高成本实验、难回退操作或共享状态修改；
- 新证据推翻关键假设，范围／成本明显扩大，或连续工作未减少关键未知；
- 长任务恢复、重要交接、阶段结束或最终验收；Agent 系统 MVP、工作流替代、父任务或其他长期行为能力进入自然观察或完成判断前必须进入；
- 模型、推理强度、上下文、工具、环境或 Agent 组合会显著影响质量、成本或风险。

普通事实查询、低风险局部编辑、机械格式化和明确易回退步骤不进入。同阶段没有新证据或风险时不重复检查；选择普通路径后，只有说明实质变化才能再建议升级。

## 二、恢复真正的问题

从现有上下文、当前权威和任务状态恢复，不让用户重复已知内容。分开写：

- **原始问题**：什么状态不理想，为何值得处理；
- **期望结果**：什么会变好，如何观察；
- **背景与症状**：帮助理解但不替代问题；
- **用户或 Agent 假设**：待检验的解释；
- **候选方案**：当前想到的做法，不自动升级为需求；
- **约束与授权**：不能做什么，哪些决定仍归负责人；
- **当前阶段**：本次只推进哪一部分。

解释差异会改变方向时先问一个最小问题；否则以可逆假设继续并写明失效信号。

## 三、找到当前最值得发力的位置

识别当前主要瓶颈属于哪一类，可以组合，但必须指出主瓶颈：

- 问题或需求尚未界定；
- 缺少会改变决定的事实或证据；
- 有多个方案但取舍不清；
- 方案清楚但实施、诊断或验证受阻；
- 风险、权限、共享状态或协作所有权不清；
- 资源、上下文、模型能力或运行环境不匹配；
- 方法本身未知或不适合。

把“最容易继续做的事情”和“最能减少关键未知或推进结果的事情”分开。优先解决会改变后续路径的瓶颈，不因为已有计划、Issue、工具或半成品就默认继续。

## 四、决定普通处理还是方法介入

普通路径始终有效。只做足以改变下一步的粗粒度比较：

- 选错方向的预期损失；
- 方法可能改善判断的幅度；
- 获取信息、运行方法、延迟行动和后续维护的成本；
- 行动的可逆性、风险和反馈速度；
- 负责人介入或额外 Agent 的协调成本。

ROI 用高／中／低或数量级，不伪造精度。低成本可逆行动能更快反馈时优先行动；会改变长期架构、高损失决定或大量后续工作时才加深分析。

### 默认优化什么

ROI 默认优化**总周期、有用吞吐和负责人注意力**，不默认优化最小改动量。文件少、diff 小、单步快、少问一次负责人或未经总体比较就渐进投入，都是代理指标。**“渐进默认”与“最小 diff 默认”是同一类偏差**；完整投入若更能减少串行等待、返工和判断税，就选它并保留相称证据、停止与修正规则。

更完整做法若显著减少返工、确认或串行等待，通常优于反复补丁；若扩张只为“看起来完整”且不减未知或后续成本，就缩小。判据是“对原始问题和父目标的净贡献减去总成本”，不是改动量；资源充裕而负责人注意力稀缺时尤其如此。

## 五、选择、组合或发现方法

第一版使用一个普通路径和六类方法路线。它们不是六个必须调用的 Skill：

1. **需求／问题建模**：区分问题、原始诉求、衍生诉求、背景、假设和方案；
2. **对齐与结构化问询**：暴露前提、分歧和决定依赖；若选择 `grilling`，必须遵守它自己的同意与退出合同；
3. **受限调研与取证**：先说明调研支持什么决定、哪些证据会改变判断、范围和停止条件；存在当前知识时先走知识维护；
4. **攻防／反证**：构造可信替代解释、失败路径或反例，攻击当前问题定义与方案；
5. **ROI／选项与边界决策**：比较收益、实现和维护成本、Agent 决策税、风险、依赖、可逆性及暂缓价值；
6. **最小实验／MVP 验证**：用最小可逆产物检验最重要假设，再用真实反馈修正模型。

### 按类型学查方法卡

六类路线是控制器的稳定骨架，个体方法的登记、成本、证据和退出规则按需保存在 [`references/method-registry/`](./references/method-registry/README.md)，不塞回常驻描述或本节正文。当普通路径不足且当前主瓶颈已经初步归型时：

1. 先读取 [`references/method-registry/INDEX.md`](./references/method-registry/INDEX.md)，按 P1–P5 主类型查询；P6–P8 只使用补充索引，O0 直接退出到普通路径，U 先用一条区分证据重新归型；
2. 只读取与当前类型、风险和成本最匹配的少量卡片，通常先选一张主卡；需要组合时同时服从索引与卡片的组合上限，不把方法全串起来；
3. 逐卡比较来源等级、能力证据等级、判断税、负责人注意力与退出条件。M0 只可人工点名，或在明确说明“未验证”后作为建议，不得成为默认触发；M1 只在相同边界下建议；更高等级仍不绕过自己的触发合同；
4. 同意、授权、风险、写入所有权与可逆性是硬门。类型命中、索引排序、外部方法成熟或证据升级都不能产生额外权限；`grilling` 的明示同意门尤其保持不变；
5. 卡片不可读、相互冲突或都不匹配时，退回本节六类路线或普通路径，如实记录发现性缺口，不临场编造一张已验证方法。

### 路线 3 的可执行形状：研究、选项、计划

只在已经选择受限调研时使用这一形状；不要求普通任务生成固定文件，也不把阶段名称、目录或评论标记变成新的状态机。产物可以留在当前任务或 Issue，但另一个执行者必须能分清以下三层：

1. **研究层**：把事实、约束和未知分开。每条会影响决定的主张标注来源等级：`本次直接验证`（实际运行且可重复的命令、实验或观察）、`一手来源核验`、`二手转述`、`未核验推断`；同时记录对象、版本／时间、环境和适用边界。等级说明来源与核验距离，不自动替代对来源质量的判断。能够低成本取得直接验证或一手来源时，不用二手转述冒充已核验前提；暂时只能取得转述时，把依赖它的结论保留为待验证。
2. **选项层**：形成至少两个可信方案，并比较它们与现有架构的适配、依赖的假设、主要代价与风险，以及各自需要怎样验证。确实没有第二个可信方案时，列出已排除方向及证据，不为凑数伪造备选；“维持现状”只在它确实可行时作为方案。推荐必须指出用了哪一级证据、哪些未知会使选择翻转。
3. **计划层**：把选中方案转换成可检验行动，列出实际要运行的命令或检查、暂不运行的项目与理由、失败门、风险、开放问题和完成定义。每个关键假设至少对应一个验证面；未执行项和剩余缺口不能被“研究完成”或计划文本掩盖。

这三层是证据分区，不是 `research.md → options.md → plan.md` 的强制产物链。它也不改变后文的产品证据等级：来源核验等级回答“这条研究主张从哪里来”，阶段结束的证据等级回答“整个能力最多被证明到哪一步”。

### “最小”指的是哪一种最小

这两件事都合法，但目标不同，混用会造成能力静默回退：

| | 验证关键未知的最小实验 | 产品交付的最小完整闭环 |
| --- | --- | --- |
| 目的 | 让一个会改变方向的假设尽快被证实或证伪 | 让一项能力在真实使用中端到端可用 |
| 完成判据 | 假设有了结论，无论正反 | 用户或父目标能实际走完整条路径 |
| 允许缺什么 | 可以缺完整性、鲁棒性、可发现性 | 不能缺路径上任何一段必需能力 |
| 典型失败 | 为了“做完”而扩张成半个产品 | 为了“diff 小”而砍掉闭环中的一段 |

选择前先说明这次属于哪一种，并按对应判据收口。**不要用“最小实验”的标准验收一次产品交付**：实验可以只覆盖一个假设，交付不能只覆盖闭环的一段而声称能力已经具备。也不要把一次实验升级成产品承诺——它需要自己的证据等级。

### 路线 4 的可执行形状：多视角攻防

攻防分轻重两级。**轻量前置**由单 Session 在时间盒内预演失败原因、缓解动作与责任人。**重型形状**只用于产品决策、长期边界或共享架构。下文是唯一执行定义；方法卡只保存选择、成本、证据与指针，CF-5 只承载角色拓扑、所有权和交付适配。

启动判据：攻击对象已经写成可被攻击的明确模型（问题定义、方案或合同），且选错的预期损失高于多 Session 协调成本。对象还写不清时先回到路线 1，攻击一个不存在的靶子只产生噪音。

推进单位是**轮**：每个已分区视角一轮交一条自足评论。标准两轮——第一轮至少两个独立攻击视角，第二轮至少两个未参与者交叉裁决，因此下限为四个独立 Agent／Session；第二轮只形成候选，不实施。产出按下表执行：

| 构件 | 可执行要求 |
| --- | --- |
| 角色分区 | 按真实攻击面枚举至少两个视角（例如调度、并发、生命周期、数据归属、整体 ROI 红队），每个视角一个独立 Session，不在同一上下文里自我红队 |
| 每人一条自足评论 | 每个执行者只发布一条带轮次与角色标识的评论，另一个 Session 不读派发上下文即可复核 |
| 必答结构 | 每条评论必须回答：当前对象最可能错误的三点／推荐方案／最强反方／失效条件／需要实验的未知／MVP 必须具备与明确不做 |
| 事实推断分开 | 引用来源与自身推断逐条分开标注，二手转述注明未核验 |
| 上限时间 | 每轮设定时间盒，到点收口，不追求穷尽 |
| 交叉裁决 | 第二轮至少两个未参与者：一个检查各方案能否组合、有无自相矛盾或状态遗漏；一个站在“尽量不自建、降低判断税”的立场攻击整套方案 |

停止判据，命中任一即收口：两轮完成；时间盒用尽；新一轮不再产生会改变决定的新攻击；对象本身被证伪，需要回到问题界定。独立上下文、真实不同的视角和接触外部证据是本形状有效性的关键变量，不是可省略的成本；同一上下文的自我审查不能替代新 Session 交叉。

若这轮攻防属于已经登记的 Agent 系统迭代事件，并且需要跨 Session 恢复裁决与后续复核，按需加载 `self-improvement`，读取其 `references/iteration-receipt.md`，只把各视角和裁决实际产生的增量证据交给当前回执的唯一写入者。第一轮发现仍是候选；这项引用不调用自我改进、不复制十字段，也不产生第二个控制器。

### 路线 6 的可执行产物：预注册实验卡与收口卡

最小实验把第七节小合同具体化为一对卡片，随任务记录或 Issue 保存，另一个 Session 不读聊天上下文即可复核方法是否真的运行：

| 实验卡（开始前写死） | 收口卡（结束后填写） |
| --- | --- |
| 假设：我们相信〈做法〉会带来〈结果〉，观察到〈可测信号〉即证实 | 观察：实际发生了什么，与预注册判据逐条对照 |
| 检验方式与度量：怎么检验、量什么 | 结论：假设被证实、证伪还是仍未知 |
| 成功阈值：跑前写死的判据 | 方向改变：这个结论改变了哪个决定或路径 |
| 停止条件与失效信号 | 遗留未知与下一步归属 |

预注册纪律：成功判据在实验开始前登记，开始后只可作废重登、不可原地修改，防止事后合理化。解释结果前先排除测量与触发系统本身的故障（判据没有运行、Skill 未加载），再谈方法效果。实验卡是第七节小合同在“最小实验”分支的具体化，不复制本节判据表；与 `self-improvement` 的最小可逆资产维持单一事实源约定。

可以串联少量方法，例如“先界定问题，再受限调研，最后做选项分析”；不要为了显得完整而全部运行。已有合适 Skill 时按其边界调用；没有时只执行当前必要的最小步骤。若这些类别明显不足且方法选择会显著影响结果，先做一次受限的学术／工业方法调研，不建设无边界方法目录。

## 六、选择与任务匹配的执行配置

方法选定后，再检查执行条件是否适合：

- 当前模型和推理强度能否处理任务复杂度与风险；
- 当前上下文是否包含必要权威、证据和状态，是否被历史噪声淹没；
- 是否需要搜索、代码执行、浏览器、MCP 或其他外部反馈；
- 一个 Agent 是否足够，还是独立复核或并行分工的收益高于协调成本；
- 当前环境、权限、工作区和共享资源是否允许安全执行。

“最优”表示当前证据和成本下任务适配，没有必要证明全局最优。没有切换模型、环境或协调后端的实际能力时，如实记录限制或请求决定，不声称已经调整。协作有净收益且授权清楚时，使用可用的协作行为和真实后端。

## 七、建立本阶段的小合同

开始方法或实质行动前，写清与风险相称的最小合同：

- 本阶段要减少的关键未知或要作出的决定；
- 使用的方法及选择理由；
- 需要的证据和可接受近似；
- 验证面、预期来源等级及不运行项的理由；
- 时间、Token、工具、人工注意力等成本上限；精确值昂贵时用近似；
- 停止、升级、降级、换路条件及失败门；
- 预期产物、完成定义与验收方式；
- 当前授权覆盖什么，什么必须请求负责人决定。

低风险任务可隐含表达，不强制制表；方向、授权或长期状态改变时再写任务记录。

当前 Agent 系统阶段已经登记迭代事件，或到达需要跨 Session 恢复因果的自然里程碑时，按需加载 `self-improvement` 并读取其 `references/iteration-receipt.md`；APS 继续决定路线、调整和证据等级，只把本阶段结果写回同一回执。普通任务不为格式完整创建回执，其他 Skill 也不复制协议正文。

## 八、按反思节律在关键节点调整路径

### 行动前事实与决定价值双门

本小节是 G1–G3 的唯一规范正文；调用处只路由，不复制判据或新增状态、回执、等待来源。三门分别在实质行动、形成负责人动作、评估 CF-6 前运行：

1. **G1｜实测或未知。** 能力、权限、网络、版本、资源新鲜度或工具状态主张，只要会改变做不做、下一动作、执行者或工具就触发；有低成本、安全、只读或易回退的直接探针则运行并记录对象、环境／版本、时间、探针和结果。探针不可得、昂贵、有副作用或需新增权限，就写“未知”，走可回退普通路径并登记翻转条件。直接证据可得时不用记忆或转述代替；不复测普通背景事实，也不授权安装、改凭据或宿主环境。
2. **G2｜无回复五维反事实。** 创建负责人请求或投影等待前，写明“负责人暂不回复”的普通路径，比较**下一动作、授权边界、风险暴露、资源投入或总成本、不可逆或有时限的机会**。五项均相同就不形成负责人动作、不投影等待，在授权内继续并保存推荐、置信、最强反方和翻转条件；任一不同才进入现有完整负责人决定协议。拿不准不自动升级：低影响可回退则保持未知；潜在损失高、默认继续扩大暴露或时限机会可能消失，就写明差异。沉默不是授权。
3. **G3｜三方审阅经济门。** 只有 G2 证明决定真实阻塞、现有替代授权覆盖该决定，且解除阻塞价值高于三席与时间盒总成本，才评估 `orchestrated-collaboration` 的 CF-6；否则走负责人直接决定或普通路径。CF-6 身份、密封、裁决和授权合同仍归其形态卡，结果不扩张授权。

迭代事件把证据／未知、普通路径与差异、授权、翻转条件和成本写入现有回执；普通任务只留解释选择的短记录。判据在行动前预注册，运行后只对照；验收同时看漏报、返工、核验成本和负责人注意力，不以请求数下降替代。

一个真实工作波次为常规周期；无波次的长任务只在重要阶段结束取样。纠正、重复失误、能力回退、抽象循环或预注册翻转条件即时旁路；墙钟和资源状态不触发，也不建日历调度或自动化。

短查原始目标／关键假设与实际结果／来源，标出最重要偏差／复发、主瓶颈及方法配置变化，确定下一行动、停止条件与检查点。当前问题或方法由本 Skill 换路；跨任务行为缺口转 `self-improvement`。

据此继续、换路或退出；方向未变不生成固定报告。连续两波反思成本高于发现或避免返工的收益，就退回按需模式；只有新证据才能再次常规化。

### 阶段结束与最终验收的附加检查

普通、低风险、容易回退且不改变长期行为的任务只做上述短检查。Agent 系统 MVP、工作流替代、父任务或其他长期行为能力再加下面六项；看行为影响而不看交付件数量，不能用子任务或计划完成度替代：

1. **父目标贡献**：整体实际改善原始问题和父目标的哪一部分；只确认子任务或计划完成不算通过；
2. **能力回退**：对照当前基线、参考能力和被替代方案，列出保留、删除或弱化；后两者必须有证据且被有意接受，不能静默丢失；
3. **证据等级**：明确当前证据最多支持哪一级，不把低一级说成高一级：

   ```text
   实现完成 → 当前交付验收 → 样本有效 → 产品采用 → 长期依赖
   ```

   箭头只表示证据增强，不是流程或目标；每一级各需证据，前一级不自动解锁后一级，“产品采用”和“长期依赖”还需要负责人决定。

4. **负责人可见 ROI**：需负责人决定时，收益、成本、失败、限制、可信替代、推荐和待决定事项必须进入其可直接访问的审阅面；聊天、终端、本地文件或研发记录不算；
5. **完成结论**：实际完成、缺口和下一责任人；不把“动作已执行”写成“方案已可用”；
6. **持久行为入口**：声称能力可跨 Session／模型复用时，指出持久触发、行为载体、真实入口和可发现性证据。页面、文件、Issue、脚本或缓存本身不证明行为已接入；人工运行就如实标明。

参与建模、拆分或设计者存在同源盲区；需要未参与者做父目标级只读复核时，按第十节路由到 `orchestrated-collaboration`，不在本 Skill 内自建审查角色、评分或评测平台。

### 发现缺口后由谁处理

先分类缺口，不把“发现缺口”本身交给负责人：

- **授权内的客观缺口**（能力静默丢失、证据等级过高、审阅面缺失、结论与证据不符）：判定 `revise`，直接修正或提出最小方案后继续；
- **产品目标与取舍、风险偏好、需要扩大授权**：按第九节合并成一次负责人决定；
- **只影响 Agent 自加假设**：记录后继续。

没有完成父目标贡献和能力回退检查之前，不得声称父目标或产品闭环完成。

## 九、决定什么需要人判断

先执行第八节 G2。不同产品目标／长期边界、授权扩大／共享系统修改／明显损失差异、证据不足却必须作高影响决定，以及取决于人的偏好、业务信息或风险承受能力，都是五维差异的常见来源；它们不是沉默授权。在授权内可直接缩范围、换可逆方法或调整顺序。

合格输入才交给现有负责人决定协议；由它形成问题、少量选项、推荐、主要收益／代价和普通路径，本 Skill 不复制请求、授权或消费规则。

## 十、完成并路由结果

阶段完成后：

- 目标、授权、决定、进度和下一步进入任务状态；
- 只有有效且通过准入的结论进入知识；
- 纠正、失败、实验和方案理由进入任务证据或研发记忆；
- 可跨任务复用的行为缺口进入 `self-improvement`，不在本 Skill 内改系统；
- 需要协作，或需要另一个未参与拆分和实现的 Agent 做父目标级只读复核时，由 `orchestrated-collaboration` 与真实后端提供所有权、派发和通信；
- 权威变更须由负责人确认。

返回原任务，不把问题求解治理变成长期元项目。
